The input image is already a mosaic — a synthetic rendering of a polygon-mosaic CSV array (each solid-colour polygon separated by thin dark grout lines is one tile). Re-render it so each tile looks like a real stone tessera photographed from above, WITHOUT changing tile positions, tile shapes, or tile colours. The only change from the input is added stone character on the surface of each tile.

═══ Rule #1: PRESERVE TILE GEOMETRY EXACTLY ═══
- Every tile in the input remains a tile in the output at the same position and the same shape. No tile is moved, resized, rotated, split, merged, added, or removed.
- Tile boundaries line up pixel-for-pixel with the input. The grout lines run in exactly the same places, at the same width. The tile count is identical.
- If you overlaid the input on the output, every tile boundary would coincide.

═══ Rule #2: PRESERVE TILE COLOURS EXACTLY ═══
- Each output tile's base colour IS the input polygon's fill colour — same hue, same saturation, same lightness. Sample the input pixel and use that. No palette remapping, no hue shifts, no desaturation, no "period-appropriate" pigment substitution.
- Bright, saturated, synthetic-looking input colours stay bright and saturated in the output. If the input has hot pink, the output has hot pink.
- Held next to the input, the two mosaics show the SAME colour scheme.

Stone artifacts (added on top of the preserved base colour):
- Fine natural veins: 1–3 thin veins (1–3 px wide) drift diagonally or curve across the tile face on roughly half of the tiles. Vein colour is a slightly darker shade of the SAME hue as the tile's base — never a switch to a different hue.
- Gentle mottling / grain: a soft non-uniform tone across the tile face so it doesn't look like a flat digital fill. Subtle enough that the tile still reads as its input colour from a step or two back.
- A few sparse specks (1–2 px dots) on some tiles, slightly darker or lighter than the base. Most tiles have none or a couple.
- Small edge wear on maybe 15–25 % of tiles — a chipped corner or a shallow crack (1–3 px). Does NOT extend into the grout or change the tile's outline.
- Matte surface, no gloss, no reflections, no highlights on any specific tile.

Grout:
- Same pixels as the input grout, same width, same layout. Dark, uniform charcoal-to-near-black (#1a1a1a to #333) with a hint of natural variation.
- Grout lines are continuous — no gaps.

Lighting and framing:
- Perfectly even, diffuse illumination across the whole mosaic. No hot spots, no directional shadows, no vignetting.
- Strict orthographic top-down view. No perspective, no tilt.
- The mosaic fills the frame edge to edge. No border, no surrounding background.

Output:
- Match the input's aspect ratio and resolution exactly.
- Sharp tile edges against the grout. Subtle per-tile stone artifacts as described. Each tile still clearly reads as its input colour.

Final self-check:
- Tile positions, shapes, and grout are unchanged from the input.
- Every tile's base colour matches its input polygon's colour — no palette shift.
- Stone artifacts (veins, mottling, occasional specks, small edge wear) are visible but subtle, and never override the tile's input colour.
- Lighting is even everywhere.
